# 设计共同内核与影子

## 一、共同内核（core）

内核是所有影子共享、**不可改变**的部分。它决定了影子与用户「智力相近」。

| 字段 | 必填 | 说明 |
|---|---|---|
| `source` | 是 | 画像从哪里来：用户自述、哪次对话、哪些答题记录、哪个画像文件 |
| `summary` | | 一句话概述 |
| `cognition` | 建议 | 各项 1–5 分，可以写成 `{level, evidence}`。常用维度：`abstraction` 抽象能力、`rigor` 严谨性、`working_depth` 可稳定处理的推理深度、`speed` 反应速度、`metacognition` 元认知；另有 `notes` 备注 |
| `knowledge` | 建议 | `[{domain, level, known[], unknown[]}]`。**unknown 最重要**，它划定了影子不能越过的边界 |
| `misconceptions` | | `[{concept, detail, status}]`，status 取 active 或 resolved；影子会保留 active 的误区 |
| `thinking_style` | | 可以观察到的思维习惯，例如「先给结论」「喜欢画图」「遇到难题会先找例题」 |
| `expression` | | 语体、篇幅、常用说法，例如 `{"register": "口语化", "length": "2–4 句", "phrases": ["感觉…", "应该是…吧"]}` |
| `values` / `goals` | | 与问题相关的价值取向和目标（用于决策类模拟） |
| `context` | | 当前所处的阶段，例如「期末前两周」 |
| `data_confidence` | | 0–1，表示整体证据有多充分 |
| `gaps` | | 缺少数据的方面，影子在这些方面要保守 |

### 1–5 分参照（相对于同龄、同背景的人）

| 分值 | 抽象能力 | 严谨性 | 推理深度 | 元认知 |
|---|---|---|---|---|
| 1 | 只能处理具体实例 | 经常忽略条件 | 1–2 步 | 很难察觉自己错了 |
| 3 | 能在提示下概括出规律 | 主要条件能顾及，细节会漏 | 3–5 步 | 被追问时能察觉 |
| 5 | 能主动构造抽象模型 | 条件、边界、特例都考虑到 | 长链条推理且能保持稳定 | 能准确预判自己哪里会错 |

**从画像推断内核的规则**

- 只写有证据的内容。没有证据的维度宁可不写，并把它列进 `gaps`。
- 「不会」和「会但容易错」要区分开：前者写进 `unknown`，后者写进 `misconceptions` 或 `thinking_style`。
- 不要推断健康、政治、宗教、民族等敏感属性，也不要给人格贴标签。

## 二、影子的组成

```
影子 = 共同内核（不变） + 视角 lens（必选） + 场景 scenario（可选） + 时间 time（可选） + 小幅调整 adjustments（可选）
```

### 内置视角（`lens.key`）

| key | 名称 | 关注点 | 适合用来 |
|---|---|---|---|
| first_principles | 第一性原理 | 从定义和基本规律出发推导 | 看用户能否从根本上推出结论 |
| pragmatist | 实用主义 | 最快的解法、有什么用 | 预测考试或应用时的第一反应 |
| skeptic | 怀疑者 | 找前提、漏洞、反例 | 看用户能发现哪些问题 |
| intuitive | 直觉 / 图像 | 物理图像、几何直观 | 看用户的直观理解 |
| analogist | 类比者 | 与熟悉的东西联系 | 预测迁移学习和错误的类比 |
| detail | 细节控 | 条件、边界、符号、单位 | 暴露细节上的疏漏 |
| big_picture | 全局观 | 在知识体系中的位置 | 看知识结构 |
| teacher | 讲解者 | 要讲给别人听 | 检验是否真正理解 |
| confused_self | 困惑的自己 | 最可能卡住的地方 | 预判卡点（教学中最常用） |
| risk | 风险视角 | 哪里会出错、代价是什么 | 决策和方案评审 |
| creative | 发散者 | 推广、变式、新问题 | 探索性问题 |
| devils_advocate | 唱反调 | 站在结论的反面 | 检验观点是否稳固 |
| stakeholder | 他人视角 | 站在老师、同学、面试官、客户的立场 | 换位思考 |
| emotional | 感受与动机 | 兴趣、焦虑、动力 | 学习规划和人生决策 |

如果需要自定义视角，提供 `focus`（关注什么），也可以加 `questions`（这个视角会自然问出的问题）。

### 内置场景（`scenario.key`）

exam（限时考试）· tired（深夜疲惫）· discussion（与同学讨论、被追问）· explaining（给别人讲解）·
project（在实际项目或应用中遇到）· interview（面试）· relaxed（放松探索）

场景会影响速度、细致程度、情绪和表达，**不会**影响能力上限。疲惫或紧张时出错率升高，但不会因此突然学会新知识。

### 时间（`time`）

- **past**（过去的自己）：例如 `offset: "-3个月"`，并用 `knowledge_overrides` 写明当时还不会的内容。依据可以是课程进度或画像历史。
- **future**（未来的自己）：例如 `offset: "+6个月"`，必须写 `assumptions`（例如「完成了边值问题的学习」「误区已被纠正」），
  可以相应地改变知识和能力。成长幅度要符合用户近期的实际进步速度，不要想象成另一个人。

### 小幅调整（`adjustments`）

`{"trait": "质疑倾向", "direction": "+", "magnitude": 1, "note": "..."}`，magnitude ≤ 2。
可以调整的是关注点、风格、情绪、耐心、冒险倾向等。**当下**的影子调整能力维度时（rigor、abstraction、知识等），
脚本会拒绝。

## 三、按目的挑选影子组合

| 目的 | 推荐组合（2–5 个） |
|---|---|
| 预判学生在新题上的思路和卡点 | confused_self + pragmatist（exam）+ intuitive |
| 检验对一个概念的理解深度 | first_principles + teacher + skeptic |
| 用户对一个观点或方案的多角度反应 | skeptic + pragmatist + risk + stakeholder |
| 学习规划和决策 | emotional + big_picture + future（+6 个月，pragmatist） |
| 观察成长 | past（−3 个月）+ present + future（+3 个月），三者用同一个视角 |
| 自我反思 | devils_advocate + stakeholder（例如老师）+ emotional |

挑选原则：

- **正交**：每个影子都应该有可能得出不同的结论。挑选时先自问：这个影子会说出别的影子说不出的话吗？
- **对准问题**：为一个具体问题挑选的组合，比一套固定组合更有用。
- **控制变量**：观察成长时只改变时间，观察场景影响时只改变场景，这样分歧才能归因到具体的因素上。
