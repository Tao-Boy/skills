# 运行模拟、综合与校准

## 一、扮演影子：防泄漏检查清单

Agent 的知识和推理能力通常远高于用户，模拟时最大的风险就是把自己的水平带进影子。每个影子作答后逐项检查：

- [ ] **知识**：有没有用到内核 `unknown` 中的内容，或者内核里完全没提到的进阶知识？如果有，就改成卡住、猜测或绕开。
- [ ] **术语**：用的词是否超出了用户的水平？例如用户不会说「唯一性定理」，就不要让影子说。
- [ ] **深度**：推理步数是否超过了 `working_depth`？严谨程度是否超过了 `rigor`？
- [ ] **误区**：相关的 active 误区有没有体现出来？视角可以让影子更容易或更难察觉误区，但影子不会凭空「知道」正确答案。
- [ ] **元认知**：`metacognition` 低的影子往往察觉不到自己错了，confidence 可能偏高；不要让它表现出超出内核的自我觉察。
- [ ] **风格**：篇幅、语气、常用说法是否像用户本人？不要写得比用户更规范、更完整。
- [ ] **数据缺口**：落在 `gaps` 范围内的判断，是否已经降低了 confidence，并写进了 uncertainties？

检查结果写进 `self_check`（`beyond_core` 是否为 true，以及 notes）。如果发现泄漏，先修正，再重新 `add`。

### 隔离

- 最好的方式：每个影子交给一个独立的子代理，只给它这个影子的简报（`--brief-dir` 生成的单个文件）。前提是环境支持子代理，并且用户同意。
- 在同一个上下文中依次模拟时：每次只读当前这个影子的简报，作答完立即提交，**不要回头参考**前面影子的回答；
  也不要为了「制造差异」而刻意和前面的影子唱反调。差异应当自然地来自视角的不同。

## 二、综合

| 字段 | 写什么 |
|---|---|
| `consensus` | 所有或大多数影子一致的地方。这往往就是用户最稳定的反应 |
| `divergences` | **必填**。哪些影子在哪里分歧，以及分歧是由哪个因素（视角、场景、时间）造成的 |
| `blind_spots` | 所有影子都没想到的东西。这通常反映了内核层面的知识或能力缺口，是教学和反思中最有价值的信息 |
| `insights` | 由分歧和盲点得出的、关于用户的新认识 |
| `prediction` | `most_likely`（用户最可能的想法）、`confidence`（0–1）、`alternatives`（其他可能）。以场景最贴近真实情况的影子为主，并参考共识 |
| `recommendations` | 下一步：怎么教、怎么问、提醒用户注意什么 |

预测的 confidence 不应高于内核的 `data_confidence` 太多。

## 三、保真度评分（run compare）

拿到用户的真实回答或想法后（逐字记录在 `actual` 中），给每个影子打分：

| 分数 | 含义 |
|---|---|
| 0.9–1.0 | 结论、思路和主要错误都与用户一致，表达风格也像 |
| 0.7–0.8 | 结论一致，思路或细节略有不同 |
| 0.4–0.6 | 部分一致：抓住了一些关键点，但有重要偏差（例如高估或低估了用户的觉察力） |
| 0.1–0.3 | 基本不像：结论或思路明显不同 |
| 0 | 完全相反，或者明显泄漏了 Agent 的知识 |

注意：

- 场景不同的影子（例如「考场上的我」）不一定要与用户此刻的回答一致。打分时要考虑场景是否匹配，并在 notes 中说明。
- 在 `lessons` 中写下可以推广的结论，例如「误区比预想的更顽固」「用户比内核描述的更爱画图」。
- 有了足够的 lessons 之后：
  - 偏差来自内核：用 `core set --reason` 更新内核（例如把 metacognition 从 3 调到 2）；
  - 偏差只出在某个影子身上：用 `update` 修正它的视角设定，或者 `retire` 让它退役。
- 对比 3 次以上，平均保真度仍低于 0.5 的影子，`list` 会把它标记出来。

## 四、伦理边界

- **知情**：影子是关于用户本人的模拟，应当在用户知情、并且为了用户自身目的（学习、反思、决策）的情况下使用。
  教学者模拟学生时，只用于改进教学，不用于给学生打分或贴标签。
- **标注**：展示时始终标明「模拟」和置信度，不把影子的话说成「你会这么想」「你就是这样的人」。
- **不替代本人**：不用影子替用户做决定、对外发言或签署任何东西；如果模拟和用户本人的表达冲突，以用户本人为准。
- **不操纵**：不利用影子去寻找说服、施压或利用用户弱点的方法。
- **敏感信息**：内核中不放与目的无关的个人信息，也不推断敏感属性。
