# 审阅指南：内容校验、结构规划与分类

目标是用尽量少的阅读量，做出可靠的判断。不要通读全书。每个判断都应当有证据：某几行原文、某条 issue，
或者 outline 中的字数统计。

## 一、MinerU 常见问题速查

| 现象 | 典型表现 | 处理 |
|---|---|---|
| 标题层级被拍平 | 所有标题都是 `#`（issue `heading.flat`） | 草案已按编号重建，审阅时重点看 `?` 标记 |
| 目录被识别成标题 | 书前出现一串没有正文的「第X章」「1.1」 | 草案会把目录区的标题放入 `demoted`；检查目录区是否在正确的位置结束 |
| 页眉、页脚、页码混入正文 | 书名或章名反复出现（`noise.repeated_line`）、单独一行数字（`noise.page_number`） | 确认后放进 `noise_lines` |
| 标题漏识别 | 章节特别大（`!`），编号跳跃（`heading.numbering_gap`） | 用 `show` 找到标题所在行，新增 section |
| 正文被识别成标题 | 标题过长（`heading.long`）、标题其实是「例 1.2」或「图 3」（`heading.is_unit`） | 从 sections 中删除，或确认已经被降级 |
| 跨页断段 | 段落在句子中间断开，下一段直接续写（`text.split_paragraph`） | 一般**不必修**，因为检索不受影响。只有影响定理陈述这类关键内容时，才用多行 fix 合并 |
| 公式识别错误 | 花括号不配对（`math.braces`）、`\begin` 与 `\end` 不匹配（`math.env`）、`\left` 与 `\right` 数量不一致（`math.leftright`）、行内 `$` 个数为奇数（`math.inline_unbalanced`） | 能从上下文确定正确写法的才修；不能确定的记进 notes |
| 公式块未闭合 | `math.unclosed`（error） | 一定要看。往往是缺了结尾的 `$$`，后面的段落被吞进了公式块。用 fix 补齐，或者记入 notes |
| 多个公式被合并 | `math.long` | 一般不修，记录即可 |
| 表格结构错误 | `table.cells`、`table.unclosed` | 不修 HTML 结构；严重时在 quality 中说明 |
| 图片缺失 | `image.missing` | 确认 `images/` 目录是否和 md 放在一起；不修改正文 |
| 乱码 | `text.garbled` | 抽样查看；成片乱码时在 quality 中注明所在范围 |
| 双栏错序 | `text.long_paragraph`，或段落语义跳跃 | 无法无损修复；在 quality 中注明 |

## 二、内容校验步骤

1. 读 `issues.md` 的统计表，按 error → warn → info 的顺序处理。
2. 每一类 issue 取前几条，用 `tkb show <work> -l <行号> -C 3` 查看上下文，判断是系统性问题还是个别问题：
   - 系统性问题（例如某种 OCR 错误反复出现）：在 notes 和 quality 中记录。如果有明确、统一的修正，可以逐条写 fix。不要为此去改源文件。
   - 个别问题：确定原意的写 fix，不确定的跳过。
3. 随机抽检：`tkb sample <work> -n 10` 抽正文，`--kind math -n 10` 抽公式，`--kind table -n 5` 抽表格。逐个判断：
   - 文字是否通顺、有无错字
   - 公式 LaTeX 是否合法，含义是否与上下文一致
   - 表格结构是否完整
4. 写 `book.quality`：总体评价（良好 / 一般 / 较差）、主要问题及其范围、已经做过的处理。

### fix 的写法

- `find` 取能唯一定位的最短片段，例如 `"\\frac{a}{b"`，不要整行照抄。
- JSON 中的反斜杠要写成两个：LaTeX 的 `\frac` 在 JSON 里写作 `"\\frac"`。
- 写完立即运行 `tkb check`。如果提示「找不到」，通常是转义写错了，或者行号不对。
- 不做以下事情：统一术语译名、改写口语化的表述、补全书中原本省略的推导、修改原书本身的错误（可以写在 notes 中）。

## 三、结构规划步骤

1. 通读 `outline.md` 的章节树（只有几百行，可以完整阅读）。
2. 检查以下各项：
   - 层级：章 → 节 → 小节是否正确嵌套；同一层级是否保持一致的 level。
   - 有 `?` 的条目：用 `show` 看前后文，判断它应属于哪一级、是不是真正的标题。
   - 有 `↑` 的条目：它原本是段落，被提升成了标题，要确认它确实是标题。
   - 有 `!` 的条目（超过 3 万字）：在该范围内找出漏识别的标题。可以用 `grep -n` 搜索源文件中的「^\d+\.\d+ 」或「^第.+节」这类模式。
   - role：前言、目录、各章的习题和小结、附录、参考文献、索引是否标对；正文从哪一节开始（在此之前是 front_matter）。
   - number：「第三章」写成 "3"，「3.2」写成 "3.2"，「附录 B」写成 "B"。编号会被 `lookup` 和 `read` 使用。
3. 编辑后运行 `tkb outline <work>`，查看新的树和字数，确认没有异常。

## 四、分类步骤

- 书籍级：参照 taxonomy.md 填写 subject、field、level，并补全作者、版次、出版社（可从前置内容中找到：`show <work> -l 1-80`）。
- 章节级：给每章、每节写 2–5 个 `topics`，使用规范术语（例如「高斯定理」，而不是「高斯的那个定理」），中英文均可（「格林函数 (Green's function)」）。
  给每章写一句 `summary`，概括这一章讲了什么，而不是评价它。
- 单元级：用 `tkb preview <work> -s <节号>` 查看自动识别的单元。对漏识别的（例如「定理」二字被加粗，但编号放在了下一行）或误识别的，写进 `units`。

## 五、完成标准

- `tkb check` 没有 error；剩下的 warning 都已经判断过（可以忽略的，在 notes 中说明理由）。
- 抽检过 2–3 节的 `preview`，单元边界合理。
- book 元数据完整，`quality` 已经填写。
- 把 `status` 设为 `"reviewed"`，然后 `ingest`，再 `verify`。
